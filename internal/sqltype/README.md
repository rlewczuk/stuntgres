# internal/sqltype

SQL type descriptors and values, text and binary codecs, coercion, comparison,
operator resolution and the type-owned evaluation plans that builtins bind.
Catalog namespaces, ownership and atomic publication belong to the engine's
`catalog`/`typedef` owners, socket framing to `cmd/stuntgres`, and FTS
vector/query algebra to `internal/engine/fts` (a leaf below this package).

## Imports

Production code imports only the standard library, `sqlstate`, `engine/fts` and
its subpackages `unicode16` (Unicode 16.0.0 tables generated by
`make generate`) and `pgencoding18` (encoding conversion). `tzdata/` is
embedded time-zone data. Provenance is in the `pgencoding18` and `tzdata`
READMEs. Most engine packages and `cmd/stuntgres` import this package.

## Descriptors, values and codecs

- A `*Descriptor` owns text input/output (`Input`, `Output`, `SQLLiteral` and
  their `*WithEnvironment` forms) and binary receive/send
  (`BinaryInputWithEnvironment`, `AppendBinaryWithEnvironment`); callers supply
  the captured temporal, locale, catalog, role and domain-check environments.
  Server Bind, row output, FunctionCall and COPY reuse these methods; there is
  no conversion registry and no second integer parser (`ParseInt8` serves COPY
  options).
- `ClientEncodingPolicy` owns a copied immutable inbound/outbound conversion
  pair, with scalar identity only. Core supplies actual default providers;
  missing providers never fall back to a built-in kernel lookup. Conversion
  validates, counts and emits with bounded context polls and publishes no
  partial string. Append uses caller-owned capacity and restores its original
  length on error. UTF8/SQL_ASCII identity paths avoid conversion allocation.
  `EncodingReader` incrementally converts byte streams using owned fixed
  buffers, retaining incomplete characters and combined-map lookahead.
  Input/output environments enable this boundary only for byte transport;
  native Unicode APIs and immutable stored datums are not reinterpreted.
  Binary containers recurse through the same environment for textual leaves,
  keeping framing words, numeric fields, bytea and internal CHAR opaque.
- `Builtins()` returns a new builtin generation on every call: a copy of a
  template built once (`builtin_template.go`) whose descriptor pointers are
  moved into the copy. A new descriptor-pointer field must be listed in
  `descriptorPointers`.
- A `Usage` is descriptor + typmod + collation. `Value` is an immutable datum;
  shared payloads (arrays, composites, geometry, JSONB) are never mutated after
  construction. `SameDatum`/`Value.SamePayload` compare stored bits,
  independently of SQL equality. NULL belongs to the caller's framing, not to
  empty text, empty bytes or the zero `Value`.
- `ReadBrinPage` borrows immutable caller bytes and checks released page
  headers without consulting table rows. Per-column `BrinStoredColumn` values
  validate the original admitted input/class and capture the actual opclass
  storage descriptor resolved from the current catalog. Released storage-key
  overrides determine stored datum output, not a binary-compatible table alias.
  Tuple deformation walks those descriptors and renders their values with the
  caller's output environment.
  `NativeDatum` owns little-endian PostgreSQL physical datum interpretation,
  including short/ordinary and PGLZ/LZ4 inline varlena, independently of wire
  codecs. Bounds failures in undefined corrupt layouts are ordinary internal
  errors, not invented PostgreSQL diagnostics. Decoding never fetches TOAST or
  synthesizes physical pages.
- `ReadFSMPageContents` borrows immutable bytea and produces owned text from
  fixed little-endian FSM node bytes and a signed next-slot pointer. Only exact
  page size and the new-page `pd_upper` marker are checked; other headers and
  pointer ranges do not authorize extra validation. No physical pages are acquired.
- `ReadGinPage` borrows immutable bytea and validates the selected metadata,
  opaque or compressed-leaf boundary. Fixed fields use released native alignment;
  opaque flags retain recognized-bit order and a combined unknown-bit suffix.
  `LeafItems` bounds every segment, aligned stride and delta byte read, checks
  cancellation, and owns decoded physical TIDs without text reinput. Released
  seven-octet consumption uses the full seventh octet, unsigned accumulation
  and `uint32` output-block narrowing, without a 43-bit validation ceiling.
  Safe low page-version, reported GIN-version and stored offset mutations are
  not extra validation gates. Undefined corrupt layouts use the ordinary native
  layout error, never fabricated PostgreSQL SQLSTATEs or physical acquisition.
- `PgNDistinct`, `PgDependencies` and `PgMCVList` are concrete internal base
  descriptors. Non-NULL text and binary input reject with 0A000; typed NULL
  remains valid for storage, parameters and results. Checked internal producer
  constructors `StatisticsValue`/`StatisticsMCVValue` freeze real payloads once;
  `StatisticsMCVBuild` encodes checked typed dictionaries and explicit NULL/index/
  frequency items using native physical datums, never wire output. Construction
  retains no caller slices. Payload fields stay private and compatible retags
  share backing. Distinct/dependency output uses released map formatting; MCV
  output follows bytea hex/escape presentation.
  Dependency dimensions admit positive sparse attribute numbers and expression
  identities -1..-8 with the dependent last; zero, duplicates and invalid widths
  remain rejected. This producer authority does not admit SQL datum input.
  Send emits the frozen linux/amd64 little-endian serialization
  without a varlena header. Native MCV dictionaries use significant by-value
  widths, fixed reference images, or length-prefixed physical varlena payloads;
  aligned allocation extents are checked independently. Domains retain logical
  OIDs, enum words retain member OIDs, and embedded arrays retain current element
  OIDs and complete native element headers. NUMERIC and JSONB use physical
  containers rather than network headers or textual substitutes. Dictionary order
  is deterministic first-retained occurrence, not a cross-backend byte-order claim.
  `StatisticsRetainedTreeValue` is checked internal statistics replay authority
  for prepared structural text only; it grants neither SQL input nor parser trees.
- Canonical `pg_statistic` row10029 describes its exact31 released members,
  including five ANYARRAY fields; array10028 has that actual element identity.
  These self-owned builtins grant restricted catalog result authority:
  `StatisticRowValue` and `StatisticRowsValue` freeze checked rows and arrays,
  while `StatisticArrayValue` retains a genuine concrete array and its element
  usage behind a catalog ANYARRAY slot. Ordinary Composite/Array constructors,
  external non-NULL input, storage and comparison admission remain unchanged.
  Subscript/field projection and explicit text output operate on actual typed
  payloads, never serialized text storage. `ValidResult`, `SamePayload`, retag
  and authorized import retain this boundary across genuine generations.
  Builtin cloning remaps every member, element and self-owner into its own
  generation. Conditional equality's unresolved ANYARRAY diagnostic remains.
  `RebindStatisticDescriptors` rebuilds only the authentic fixed row/array pair
  when replacement retains selected builtin member generations. Unchanged
  closures keep their backing; rebuilt members, element and self-owner remain
  coherent without weakening type-provider generation checks.
- `PgLSN` retains unsigned 64-bit positions inline. Its descriptor owns strict
  slash-hex text, canonical uppercase output, typed SQL literals and eight-byte
  big-endian codecs. Comparisons and B-tree ordering use unsigned magnitude.
  Differences are exact NUMERIC; numeric offsets round the completed exact
  result once before unsigned range validation. The numeric-left addition
  signature retains its SQL-wrapper diagnostic context. Companion identity
  does not grant executable arrays or index hash support. Grouping hashes the
  unsigned bits; INET/CIDR grouping hashes family, prefix and address consistently
  with their existing typed equality.
- `Composite` freezes catalog members and rejects pseudo-type storage attributes.
  `RecordShape` freezes an anonymous expression/query-result occurrence and
  retains VOID members, including their exact typed NULLs for empty results.
  Anonymous shapes use the SQL diagnostic name `record`, independently of
  their public database type name `RECORD` and member descriptor identity.
  `RecordSignatureShape` additionally admits canonical polymorphic declaration
  members. Unresolved shapes are lookup-only, never executable values; concrete
  specialization builds an ordinary `RecordShape` with the declared labels.
  Both preserve complete member usages and coherent descriptor generations;
  `CompositeValue` copies borrowed fields, while `OwnedCompositeValue` takes
  exclusive ownership without copying. Neither exposes mutable field backing.
  Generic scalar RECORD can retain an immutable actual tuple shape and payload
  behind a deferred query descriptor, without inventing a catalog row type.
- Domains delegate physical codecs to their base, keep their logical identity
  and check fresh input; `Descriptor.RebindDomain` rebuilds a same-ID
  generation with current naming and base authority.
- REGCONFIG and REGDICTIONARY arrays use the ordinary checked array codecs and
  retain the scalar generation, including through domain elements and composite
  members. Catalog identity import is recursive and class-qualified; admitting
  these containers does not relax composite generation coherence.
- `Value.Retag` remints descriptor ownership without changing the datum. It
  requires the same type ID, domain/base identity and constraints, and rejects
  foreign hstore/lquery/ltree/ltxtquery/citext/ISN generations and enum members even for equal OIDs; only
  source-authorized catalog reownership/import remaps explicitly (`RemapHstore`, `RemapLquery`, `RemapLtree`, `RemapLtxtquery`,
  `RemapCitext`, `RemapEan13`, `RemapIsbn`, `RemapIsbn13`, `RemapIsmn`, `RemapIsmn13`, `RemapIssn`, `RemapIssn13`, `RemapUpc`).
- Installed `Ltxtquery` retains immutable canonical text and postfix Boolean
  nodes indexed into that owned text, with iterative lexer, operator frames and
  printer. Input/output and matching honor context cancellation; its associated
  array remains lookup-only.
- Capabilities (comparison, ordering, grouping, hashing, index, binary
  providers, storage admission) come from descriptor providers, never from a
  catalog OID or scalar operators alone. A missing provider fails with its own
  diagnostic; nothing falls back to text while claiming binary format.
  Pseudo identity metadata grants neither storage nor executable handlers.
  CSTRING owns text I/O and exact text-carrier datum identity without ordering;
  VOID discards text input and outputs non-NULL empty text. Their real
  result/input carriers grant no stored columns.
  Narrow builtin query-NULL usages, including ANYARRAY, require canonical
  descriptor self-ownership: copies and modified usages cannot inherit it.
  This capability is separate from polymorphic declaration authority; these
  expression usages remain non-concrete and grant neither codecs nor storage.
  Dummy pseudo input reports its SQL diagnostic before concrete codec admission;
  this does not make handlers or other signature-only identities concrete.
- `IndexClass` retains the catalog-selected method, family, input and storage
  identities. GiST classes admit exact owning geometry, network, range,
  multirange and text-search datums without a B-tree comparator. Logical
  exclusion predicates reuse their scalar owners; catalog class membership
  does not supply an otherwise missing scalar operation.
- `CitextPattern` retains genuine operand descriptors and prepared implicit text
  adapters, delegating insensitive LIKE and POSIX evaluation to the shared plans.
  Source pattern bytes and embedded options remain unchanged; regex execution
  scratch belongs to the calling statement, never the immutable provider.
- `BindCitextString` retains selected citext formals in the shared `StringPlan`.
  Its scalar mode uses declaration-bound TEXT case conversion, the existing
  regex replacement/split boundaries and ordered translation passes. Scalar
  field collection scans shared split boundaries without retaining a text array;
  ordinary TEXT plans never infer installed behavior from operand descriptors.
- `CitextComparison` binds only genuine same-generation citext operands to the
  six strict Boolean predicates. It folds lazily with database C ctype, preserves
  spelling, compares folded bytes directly for equality without an input
  collation provider, and demands ordering collation only for reached nonnull
  ordering. It grants no generic ordering, hash, grouping or index capability.
- Hstore owns immutable sorted unique key/value pairs with a separate NULL-value
  bit. SQL NULL is distinct from an empty nonnull payload. Text input uses ASCII
  scanner whitespace and byte-offset syntax errors; output quotes/escapes pairs
  in UTF8 key-byte-length then bytewise order. Duplicate keys retain one original
  value without a first/last-survivor promise. Typed comparison walks canonical
  key/value byte spans, then pair count and entry boundaries/NULL flags, without
  formatting or allocating a flattened payload. SQL operator admission is separate:
  datum ordering does not grant ordinary ordering overloads. Grouping uses that
  equality and canonical hashing, with SQL NULL in one NOT DISTINCT group.
  `HstoreHash` streams count, entry words and payload into the shared PostgreSQL
  hash state; the low 32 bits at seed zero supply the unseeded support result.
  Both kernels check cancellation within long spans and across metadata.
  B-tree/hash bindings require catalog-authenticated `HstoreIndexSupport`
  captures with exact method, family, type and nonzero member/routine revisions;
  hash binding retains both unseeded and extended support slots. Dynamic routine
  IDs never enter the builtin native-routine registry.
  Authorized generation remapping shares immutable pairs without reparsing stored
  text. The parser and typed scalar/array constructors share the owned
  sort/uniqueness finalizer. Consumers check the private immutable carrier
  without rescanning canonical invariants. Binary-search lookup distinguishes
  missing keys from present NULL values; array lookup owns fresh buffers
  preserving request shape and lower bounds.
  Key-array predicates flatten requests, ignore NULL keys and short-circuit
  without sorting or copying; containment compares exact pair bytes and NULL
  flags. Key/value projections own final TEXT[] buffers and share immutable
  strings, retaining aligned pair positions and canonical empty dimensions.
  `HstoreConcat`, scalar/array/pair deletion and `HstoreSlice` merge private
  canonical pairs without text roundtrips. Right-biased replacement retains
  complete NULL flags; key requests flatten shape, omit NULLs and deduplicate.
  Results own pair headers while sharing immutable strings; exact source
  generations are validated before whole-NULL handling.
  `HstoreArray` transfers fresh flat or rectangular TEXT-array buffers without
  copying immutable strings or exposing pairs. NULL values become typed NULL
  elements; whole NULL and zero-dimensional empty arrays remain distinct.
  `HstoreRowsPlan` checks scalar TEXT or fixed key/value RECORD usages and opens
  invocation-private cursors directly over immutable pairs. No intermediate
  arrays or pair copies are retained; present NULL values are distinct from EOF.
  Closing or cancellation releases the borrowed payload without affecting peers.
  `HstoreJSON` writes textual JSON directly from those pairs into one owned
  builder, sharing the JSON escaper and lexical number scanner with existing
  consumers. Loose detection preserves complete numeric lexemes without
  magnitude conversion; descriptor validation precedes SQL NULL.
  `HstoreJSONB` instead constructs structural string/null/bool/exact-number
  nodes directly, borrowing the frozen canonical pairs. Loose numbers use the
  existing numeric provider's normalization and range checks; JSONB output,
  comparison and hashing consume the genuine immutable carrier.
  `HstoreFromRecord` walks the actual live tuple shape and child output codecs;
  known whole-NULL tuples still emit every key with a NULL value.
  `HstorePopulateRecord` converts matching strings with destination input codecs
  and typmods in descriptor order, checks domains, and shares untouched typed
  fields. Nonempty right operands validate the result domain even when no key
  matched; unchanged payload sharing never bypasses those checks. SQL NULL and
  empty right operands retain their separate unchecked no-copy returns for an
  existing tuple. A NULL base and nonnull right operand construct a distinct
  nonnull tuple.
- Seg owns an inline fixed pair of binary32 words, significant-digit counts
  and endpoint markers. Its strict scanner and precision-aware formatter share
  the ordinary type I/O and coercion seams. Representation identity includes all
  six fields even when canonical output collapses equal endpoints to a point.
  `SegValue` validates portable payloads; `RemapSeg` preserves them under
  source-authorized destination ownership without text reinput. Scalar storage
  grants no SQL comparison, indexing, executable array or binary-codec authority.
- Lquery owns immutable canonical text validated by the C-locale label grammar,
  item/variant/label limits and aligned level-size checks. Input preserves label
  spelling, alternative order/multiplicity and explicit non-star quantifiers;
  it normalizes modifier flags and decimal ranges once. The immutable payload
  retains flat executable levels and alternatives into canonical text. Output
  and authorized generation remapping share that backing without reparsing.
- Ltree owns immutable exact path text and label boundaries validated once under
  UTF8/C grammar, with count-first path bounds and deferred label-length checks.
  A present carrier represents the empty nonnull path; NULL has separate framing.
  Source-authorized import shares compiled backing without text conversion.
  Typed comparison walks those owned labels without serialization, reparsing or
  allocation; label bytes, label length and then path depth determine order.
  Grouping shares that equality with separate SQL NULL framing. `LtreeHash` and
  `LtreeHashExtended` fold PostgreSQL byte hashes per label with unsigned release
  arithmetic, checking cancellation across labels and within scans.
  B-tree/hash keys require authenticated `LtreeIndexSupport` captures and exact
  method/type/member/routine revisions; hash keys retain both support slots.
  `Comparison.OrderingFor` checks exact source operand generations and collation.
  `IndexComparison.DatumComparison` retains flat installed support/revision stamps
  for exact kernel pairing; original catalog declarations remain with the owning
  sort capture. Neither operand capabilities nor numeric stamps alone grant
  authenticated ordering provenance.
- Ltree and lquery use ordinary concrete companion arrays, including supported
  domain elements. `LtreeArrayOperation` checks exact formal generations and
  implements the selected installed predicates/extractors. Whole NULL arguments
  are strict; visited arrays reject rank before NULL elements, before matching.
  Query arrays validate first and an empty query array does not visit paths.
  Whole-path matching uses bounded iterative dynamic programming, terminating
  immediately when a transition leaves no reachable positions. Boolean queries
  are evaluated within each path. Ancestor, descendant, whole-path and Boolean
  query extractors return the first physical entry's exact ltree carrier, or
  typed NULL when absent. Scratch is invocation-owned, never cached.
  Matching kernels do not confer additional scalar or binary-codec authority.
- Text-array input checks declared dimensions early, but child conversion and
  domain CHECK errors precede an extent mismatch, and storage grows only with
  parsed children (shared `ownedArray` guards).
- `ArrayForeachSlice` exposes immutable trailing dimensions with their original
  bounds, not SQL subscripting's rank-preserving/rebased slice. Callers admit
  rank and aligned offsets once and precompute block size. Full-rank delivery
  shares the original value; proper subslices own independent buffers.
- `int2vector` and `oidvector` own space-separated text codecs and share immutable
  array payloads with same-generation INT2/OID elements. Their constructors reject
  NULL members and preserve rank one, lower bound zero even when empty. NULL is
  separate from that empty header. Vector generation changes reown typed elements,
  never reparse text. INT2VECTOR compares signed elements lexicographically;
  OIDVECTOR compares length first, then unsigned elements. Before either vector
  comparison, canonical shape and same-generation non-NULL members are validated,
  including when different lengths would otherwise decide the order early.
  Ordinary subscripting
  lowers containers to canonical element arrays; generic array casts into vectors
  remain prohibited. Ordering providers do not grant physical index capability.
  A SQL cast that evaluates an element conversion normalizes an empty vector to
  an ordinary rank-zero empty array (NULL dimensional inquiries, cardinality
  zero). Same-element/binary relabeling and immutable generation reownership
  preserve the rank-one empty header; `MapArray` itself does not normalize it.
- `pg_snapshot` owns an immutable full-XID bounds/member payload. Text input
  validates nondecreasing membership and canonicalizes duplicates; constructors
  copy caller-owned members and indexed access never exposes mutable backing.
  Visibility is arithmetic plus membership for top-level IDs, not subxid status.
  Invalid snapshot text owns its full `22P02` diagnostic, including both ERROR
  severity fields; callers may attach literal positions or parameter context.
  Scalar text I/O and explicit text casts do not grant array, comparison or
  binary-codec capabilities.
- REFCURSOR is the noncollatable OID 1790 scalar with immutable portal-name text,
  text/binary I/O and genuine REFCURSOR metadata. Its OID 2201 array identity is a
  catalog fact, not array execution admission. Sharing text representation grants
  neither character operators nor implicit TEXT casts. A name carries no portal
  ownership; physical-session lookup belongs to the engine.
  `SameDatum` compares its immutable physical text carrier without granting any
  SQL equality, grouping or ordering operator.
- `BrinComparison` captures typed scalar min/max comparison and collation
  independently of B-tree class eligibility. Catalog-selected BRIN support
  slots retain summary operation identity, never scalar comparator callbacks.
  Diagnostic-only real class metadata does not grant an excluded algorithm.

### Type identity generations

Rename, namespace and owner changes retain logical type, enum-member and
composite-attribute identities. Codec generations remain immutable: the engine
reowns dependent arrays/domains/composite members/columns and stored recipes to
the current provider graph without re-inputting stored text. Retained native rows
continue owning their original descriptors. Fresh metadata and diagnostics name
the current type; prepared occurrence capture/recreation policy belongs to the
engine, not a codec-level stale-name retry.

Installed seg/hstore/cube/query_int/lquery/ltree/ltxtquery/citext/ean13/isbn/isbn13/ismn/ismn13/earth/lo retain real codec/manifest roles and earth
CHECK recipes after identity ALTER. Dump/Restore remaps these providers by their
validated installation identities; mutable spelling grants no provider authority.
Neither a logical OID nor lifecycle support introduces a new range provider,
general enum[] storage or an executable codec for a lookup-only installed array.
Domains over lookup-only bases retain user ownership, checks, names and immediate
base identity without gaining storage/input codecs. Builtin lookup provenance
remains distinct from these user domain declarations.

### Range families

`NewRangeFamily` creates reciprocal range/multirange descriptors with a captured
subtype `Usage`, actual B-tree class/support ordering and optional diff identity.
Builtin families retain their canonicalization policy; custom families have no
canonical function. Family selection uses `IsRange`/`IsMultirange`, not an OID
list. Range types themselves are noncollatable.

Builtin endpoints remain inline. Custom finite endpoints refer into one immutable
owned pair of typed values; merged bounds can retain endpoints from different
pairs. Empty and unbounded endpoints carry no payload. Comparison failures
propagate through normalization, operators and aggregates before publication.
`SameDatum` compares endpoint representations, never pair-pointer identity.
`MapRange` remints fresh endpoint pairs through an authorized leaf mapping for
catalog replacement; ordinary `Retag` never changes logical type identity.

`RangeFromValues`, `MultirangeFromValues` and `MultirangeFromArray` construct
through the same comparison and normalization authority without endpoint text
conversion. NULL bounds are unbounded; a NULL member is not an empty range.
Multirange constructors share this authority across builtin and custom families;
zero members construct an empty non-NULL value without invoking an input codec.
`RangeBounds` and `VisitRangeEndpoints` expose only immutable typed leaves for
the existing reference/output/dump visitors. Identity mappings preserve owned
payloads; destination generation changes allocate and rebind fresh pairs.
Custom multirange `Retag` validates immutable physical shape and reciprocal
family generations without executing a subtype comparator, including the
same-generation fast return. Changed generations use checked
`MapRange(RangeMapGeneration)` and fresh endpoint pairs; unchanged values retain
their owned payload without allocation. Builtin multirange Retag still checks
ordering/normalization invariants. Comparison-changing catalog imports are
certified separately with the operation context outside binder/catalog locks.
`MultirangeFromSource` evaluates typed member sources into that single owned
normalization buffer, without an intermediate value slice or a replacement
comparison callback.


### Soft input errors

`InputSoftError` decides whether a conversion failure is recoverable: a direct
`sqlstate.InputError` origin marker first (producers mark only their own
save-context errors; hard markers win over input-like SQLSTATEs), then the
exact-code list in `input_error.go`. It never unwraps errors or admits a whole
SQLSTATE class. Only COPY and JSONB call it, at their destination conversion
seams. SQL/JSON ON ERROR policies inspect annotations themselves and never use
or widen it.

## Coercion and operator resolution

- `PlanUnknownInputTransport` is the selected-consumer CoerceViaIO operation:
  genuine string-category output feeds concrete TEXT input while the analyzer
  separately retains logical UNKNOWN. In particular BPCHAR padding is preserved;
  ordinary BPCHAR-to-TEXT coercion trims and is not interchangeable. Rebinding
  retains this operation and rejects implicit use, non-string sources and non-TEXT
  transport targets. It adds no UNKNOWN datum/input capability.

- `PlanCoercion(source, target, context)` selects released direct providers before
  same-context array element conversion and restricted PostgreSQL string-category
  I/O. Ineligible direct declarations block fallback; there is no transitive
  search. I/O inputs at typmod -1 before destination sizing. Same-type sizing,
  domain entry checks and typed NULL ownership remain part of the immutable plan.
  `Rebind` remints its operation with coherent descriptor generations.
- `SelectCommonUsage` is the single domain/type/typmod fold for common
  expressions and anycompatible inference.
- `ResolveOperator` and `ResolveOperatorWithCoercion` share one ranking body;
  exact signatures win and no literal spelling or caller is special-cased. The
  optional pure `can(source, target)` predicate supplies implicit feasibility
  from the caller's captured catalog and is never stored or called during
  evaluation.
- `PlanBinaryCoercion`/`PlanDeclaredBinaryCoercion` capture exact descriptor
  pointers and one immutable representation mapping. `Apply` checks
  cancellation and source ownership and never consults a catalog, dispatches a
  routine, uses text or wire I/O as a memory layout, weakens `Retag` checks or
  falls back to IO. The engine owns CREATE CAST permissions and publication.
- FLOAT4 keeps exact IEEE binary32 words (`Float4FromBits`, `Value.Float4Bits`)
  through copies, Retag/import, nested leaves, binary transport and datum
  identity; constructors and arithmetic derive a fresh rounded word.

## Binary providers

- `Descriptor.CheckBinaryInput`/`CheckBinaryOutput` share the missing-provider
  boundary with receive/send dispatch without converting a fabricated value.
- Initialization timing is part of the contract: binary COPY TO initializes
  send providers after CopyOutResponse and before any row demand; binary COPY
  FROM sets up every live physical column before CopyInResponse; binary NULL
  Bind arguments initialize receive before domain constraints; row output
  initializes send on the first delivered tuple.
- Structured receive validates member OIDs/generations/typmods and grows only
  with received members, never from an announced cardinality. Wire OIDs never
  grant catalog identity.

## ISN identifiers

`Ean13`, `Isbn`, `Isbn13`, `Ismn`, `Ismn13`, `Issn`, `Issn13` and `Upc` descriptors own distinct scalar roles with packed
thirteen-digit identifiers and independent invalid-input flags. Their shared
scanner preserves raw character lookahead and ASCII separator rules. ISBN and
ISBN13 share ISBN-family input validation: short input validates its weighted
check digit before expansion. ISBN short output computes its own check digit
instead of reusing the stored EAN digit; ISBN13 and EAN13 share a validated long
formatter. ISMN and ISMN13 share short M or modern 9790 input validation.
ISMN emits short M notation directly from its packed identifier; ISMN13 uses
the validated long formatter. Formatting uses the attributed PostgreSQL 18.6
ranges in `ean13_ranges.go`.
ISSN and ISSN13 validate their modulo-11 short check digit before expanding into
the 977 family. ISSN short output preserves the invalid marker; nonzero issue
digits use long output. ISSN13 always uses long output, including zero issue
digits. SQL serialization always emits the complete compact EAN and marker,
independently of display notation.
Leading zeros, computed check digits, marked corrected inputs and typed NULLs
retain distinct identities. Explicit text I/O and assignment to text reuse the
shared coercion planner; typed text needs an explicit conversion to an installed
ISN role. UPC owns the leading-zero EAN subset and emits twelve compact digits
plus any retained marker. The shared packed conversion permits UPC to EAN13
assignment and explicit checked EAN13 to UPC, preserving the marker without
text I/O. UPC to EAN13 is a function-free relabel; only the checked reverse
direction contributes a cast function to expression-shape and evaluation counts.
Neither equal OIDs nor shared physical storage authorize other family interchange;
imports require exact source/destination descriptor authorization.

## Type families

One immutable plan per family is bound at analysis (`Bind<Family>`, validating
each formal's `Usage` and catalog authority before strict NULL handling) and
evaluated with `Evaluate(ctx, ...)`; per-call state is invocation-local and no
plan keeps global state. Files are named by family prefix (`numeric*`,
`jsonb*`, `range*`, `pgregex*`, `pgcrypto*`, ...).

- Checked arithmetic order in geometry, earth and crypto kernels is a contract,
  not an optimization opportunity; long kernel loops check cancellation.
- Arithmetic binds POINT/BOX/PATH/CIRCLE with POINT through the ordinary
  overload resolver. Coordinate complex arithmetic checks each FLOAT8 intermediate;
  circle scaling shares the released checked norm with geometry distances.
  BOX translation preserves raw corner order; multiplication/division normalize
  the two transformed stored corners, not a four-vertex bounding rectangle.
  PATH transforms allocate one private destination, preserve closure and vertex
  order, and poll cancellation. Open PATH concatenation preserves duplicates;
  a closed operand returns typed NULL, and combined size is checked before allocation.
- No geometric type gains default ordering/hash/index authority from its
  scalar operators.
- `FTSQueryPlan` checks source/result descriptor authority for query inspection
  and direct rewriting. `FTSRewriteRules` bridges actual typed SQL rule cells
  into one leaf-owned workspace, distinguishing skipped NULL rows from empty
  substitutes without exposing private query payloads or converting through text.
  Its checked `Empty` inquiry reads accumulator state without finalizing,
  rendering or reconstructing a query between SQL rule batches.
- `FTSVectorPlan` checks same-generation vector, scalar and array companions
  and exact typmods before strict NULL evaluation. TEXT and TEXT[] selectors
  retain valid usage collations while matching lexemes byte-exactly. Conversion
  transfers one owned TEXT element buffer to the generic array constructor.
  Internal CHAR scalars use the ordinary declaration, input and cast descriptors,
  validating external UTF8 text before one-byte decoding. CHAR arrays use the
  ordinary array codec and shared `ArrayElementAdmitted` policy for storage.
  Executable-array inventories include OID 1002 with its same-generation CHAR
  element, including the independent cast admission corpus; lookup-only
  companions remain separate from executable type identities.
- `CubeSpatialPlan` reads private entered endpoints without text conversion,
  normalized copies or padded coordinate allocations. Operand/result usages and
  descriptor identity are checked at binding. Ordered comparisons and sequential
  binary64 accumulation are retained; nonfinite arithmetic is not converted to
  checked SQL scalar arithmetic.
- `CubeCoordinate` validates non-NULL payload generation and reads endpoints
  without allocation or text conversion. Normalized bounds retain ordered C
  min/max selection (including NaN and signed-zero ties); signed projections
  widen int4 before absolute value and negate the selected binary64 value.
- `CubeDimensionCount` validates the exact payload generation and reads the
  stored dimension without coordinate comparisons. `CubeInfo` additionally
  inspects geometric point status; dimension-only inquiry uses the count path.
- `TransformCube` reads immutable cube and flattened INT4[] payloads directly.
  Subset preserves entered orientation and the source point flag. Bounding
  operations retain ordered C min/max selection; enlargement retains direct
  binary64 subtraction, addition and crossed-bound averaging. Bounded stack
  scratch precedes one owned result coordinate buffer, with no text roundtrip
  or padded input copies. Signature validation precedes strict whole NULLs;
  subset NULL elements precede length and index checks.
  Public point inquiry and cube output share the geometric endpoint predicate,
  recognizing coincident subset boxes without mutating their retained storage flag.
- `EarthCoordinatePlan` captures actual earth/cube/FLOAT8 generations and shares
  `EarthRadius` with the released domain checks. Checked binary64 arithmetic
  retains SQL NaN ordering, signed zero and underflow. Projection borrows private
  coordinates; ll construction owns one three-coordinate point allocation and
  checks the result through the ordinary domain input environment before wrapping.
- `EarthPointPlan` captures only builtin POINT/FLOAT8 descriptor generations and
  measures longitude-first coordinates in statute miles, independently of the
  earth domain's meter radius. Inline coordinates require no evaluation allocation
  or text conversion. Raw haversine arithmetic retains the released operation
  order, nonfinite propagation and upper clamp; descriptor checks precede NULL.
- One path walker serves JSONPath, SQL/JSON query plans and `JSONTableRows`.
  Numeric path arithmetic borrows exact decimal operands into private typed
  NUMERIC headers and reuses the numeric kernels; no provider identity escapes
  into JSONB results. Binary operands finish before singleton validation; unary
  operands materialize before emission. Invocation-local results and only
  operation-origin numeric failures use the walker's existing consumer and
  suppressible-error channels; input errors and cancellation retain identity.
  Temporal methods share the formatting compiler and field reader with explicit
  SQL versus JSONPath compiler modes. Strict compilation validates unquoted
  separators while preserving quoted literals. Compiler failures return through
  the ordinary path-execution error channel, before SQL/JSON result conversion;
  valid-template input mismatches retain their recoverable reader channel.
  Destination conversion retains its existing SQL/JSON diagnostic-class policy,
  independently of source input-soft annotations. Ordinary SQL formatting stays
  permissive, and temporal input diagnostics retain the raw decoded string.
  Invocation-owned typed items retain parsed timestamp offsets until JSON
  materialization, without changing typed PASSING serialization. Path consumers
  take an execution-owned `JSONPathEnvironment` for captured input and notices;
  ordinary JSONB paths prohibit zone-dependent promotion while SQL/JSON retains
  its own enabled policy. Private temporal headers never become result metadata
  or persistent JSONB node kinds.
- Unicode tables come from `unicode16/`; there is no ICU, cgo or host-Go
  Unicode dependency.
- `RegexpPlan` evaluation shares the statement-local `PGRegexExecution` (no
  global regex registry or program cache) and runs under the checked
  budget/cancellation authority.

### Geometry measurements and path helpers

`GeometryMeasurePlan` owns eighteen measurement/path-helper operations; radius
remains in `CirclePlan`. Formal `Usage` and same-catalog authority are validated
before strict NULL handling. PATH flags use the canonical POINT-associated BOOL,
PATH counts its `pathInt`, and POLYGON counts its `polygonInt`; equal type IDs do
not authorize foreign descriptor generations.

`isclosed/isopen(path)` read the separate closure bit, not endpoint equality.
`npoints(path/polygon)` counts stored vertices, including duplicates.
`pclose/popen(path)` replace only the immutable header when closure changes,
sharing coordinates without changing their bits, order or count; matching closure
returns the original value. Flags return BOOL, counts INT4, closure helpers PATH,
and `length(path/lseg)` FLOAT8, including strict typed NULL results.

PATH length starts at zero, visits the closing last-to-first edge first when
closed, then adjacent stored segments using checked sequential addition.
Distances use checked X/Y subtraction and the scaled hypot kernel; Infinity wins
over NaN after subtraction and representable subnormals are retained. LSEG uses
its ordered endpoints. An open singleton does no coordinate arithmetic; a closed
singleton evaluates self-distance. Traversal checks cancellation without temporary
point values, coordinate copies or text roundtrips. Open-path area returns NULL
before coordinate arithmetic.

### MAC address operations

`mac_operators.go` binds immutable descriptor-owned `MACBitwise` and `MACUnary`
providers over the existing inline MACADDR (48-bit) and MACADDR8 (64-bit)
payloads. `~`, `&` and `|` preserve the selected type and width; NOT masks the
unused high sixteen bits of MACADDR. `trunc` preserves exactly the first three
octets and clears the remaining three or five. Providers validate captured
descriptor identity and non-NULL payloads before strict typed-NULL handling,
check cancellation and perform successful evaluation without allocation.

`macaddr8_set7bit` sets first-octet mask0x02, without toggling or changing any
other bit. A six-octet MACADDR source expands with FF:FE insertion first:
`00:34:56:ab:cd:ef` becomes `02:34:56:ff:fe:ab:cd:ef`. This source829-to-result774
operation belongs only to the function provider; `PlanCoercion` does not gain
general cross-MAC casts. Unknown six-octet MACADDR8 input uses its existing
parser expansion. Rebinding constructs providers from remapped descriptors,
never stale pointers or formatted/reparsed values.

The analyzer selects the known width for an unknown operator argument and
reports mixed MACADDR/MACADDR8 AND/OR as ambiguous (42725), including typed NULLs.
XOR/shifts, general cross-MAC conversions, arrays and binary codecs are not
provided by these kernels; scalar operators also grant no default MACADDR8
ordering/grouping/index authority. Public SQL/API coverage is owned by
[`reference/geometry_network`](../../reference/geometry_network/README.md#mac-address-operations).

### Geometry relations

`GeometryRelationKind` selects both ordered operand IDs and spelling;
`BindGeometryRelation` captures canonical operand/result usages and one
descriptor generation before `GeometryRelationPlan.Evaluate` handles NULL.
POINT/BOX/FLOAT8/BOOL results keep their selected descriptor, including NULL.
Existing polygon-point and circle-circle expression providers retain their
kernels; new relation plans delegate those operations rather than migrating them.

LINE/LSEG alignment uses this plan with explicit arity. Unary catalog formals
retain left ID zero, while the single runtime operand occupies slot zero;
inactive slots must be empty. Prefix predicates compare coefficients or endpoint
axes without normalization. Parallel/perpendicular predicates preserve checked
slope/intersection arithmetic and its errors. BOX sameness applies point sameness
to each raw corner independently, including corner-local NaN exactness; area
comparisons retain their separate checked arithmetic and fuzzy predicates.

BOX and POLYGON positions use the same relation plan. BOX compares raw
high/low corners with epsilon1e-6, without renormalizing component updates;
POLYGON builds stack bounds with PostgreSQL NaN-high ordering and compares
endpoints using raw IEEE predicates. Strict directions compare opposing edges;
extent predicates compare corresponding edges. BOX `<^`/`>^` include touching
opposing edges, unlike the strict POINT aliases. Bounds traversal checks
cancellation and allocates no converted shape. POINT/CIRCLE position kernels
retain their existing ownership and relevant-axis arithmetic.

The linear, path and polygon kernels read immutable payloads, use stack-sized
linear coordinates and allocate no converted shape or coordinate slice per edge.
POINT results remain inline; BOX results own raw min-high/max-low corners.
Checked float8 order, operation-specific epsilon sites and candidate/tie order
are invariants, not algebraic simplification opportunities. Point/BOX and
point/CIRCLE containment is exact; whole-object comparisons apply their own
epsilon. Point/LINE tests the coefficient residual without normalization.
Unique LINE/LSEG intersections differ from set overlap: nonunique intersections
are typed NULL/false even when distance is zero.

Closest-point plans return a point on the second operand; equal computed slopes
and NaN closest distance preserve their NULL rules. BOX distance uses centers.
PATH iteration owns closure without appending a stored vertex; an open singleton
has no edges, point distance zero and NULL path/path distance. Filled-polygon
overlap and distance use ray crossing and closed edges; containment recursively
checks complete edges through concavities, not only vertices or bounding boxes.
Long/nested loops and recursive splits check cancellation before publication.
Point-to-polygon distance initializes its closing candidate first vertex -> last
vertex, independently of the generic last -> first traversal used by polygon
overlap, polygon/polygon distance and containment. Epsilon-horizontal/vertical
projection keeps that first endpoint's anchor; polygon/circle distance shares
the point-distance helper before radius subtraction. `TestGeometryRelationClosingEdge`
checks this distinction numerically without reversing the generic traversal.
The released Table9.36 and `REL_18_6 geo_ops.c` define the finite signature and
numerical contracts; operator admission does not grant generic comparison,
array, codec or index authority.

## Testing

Units here call codec, value and plan functions directly; public SQL and wire
behavior belong in `reference/` (mostly `types`, `operators`,
`binary_json_arrays`, `patterns_encoding`, `catalogs` and `sessions`). Follow
[docs/TESTING.md](../../docs/TESTING.md). Tests of types, operators, casts,
comparisons, collation derivation, subscripts, SQL/JSON and jsonpath that run
on a composed engine live in `enginetests/`.

Native physical datum and BRIN/B-tree/FSM byte-reader units use `RUN='^TestPageinspect'`;
GIN decoder, safety and cancellation units use `RUN='^TestGINPage'`.
The immutable B-tree reader preserves encoded TIDs, pivot trailers and posting
lists separately from page-context dead flags. Posting results use executable
generic `tid[]` (OID 1010, element 27), with ordinary array ownership and codecs;
this does not admit TID binary COPY.

- **Frames matched by tests.** `TestSimilarActualMatcherCancellation` and
  `TestRegexpSubstrCancellation` cancel only when specific frames are on the
  stack: `matchPGRegexStates`, `pgRegexWork.step`, `regexpFlags`,
  `RegexpPlan.evaluate` and `matchPGRegexTagged`. Renaming them breaks the tests.
  Other cancellation units match frame suffixes too, among them the engine
  aggregate tests in `internal/engine/functions/enginetests` (`Comparison.Compare`,
  `Grouping.PrepareKey`, `Hash` and `Equal`, `RangeAggregate.Advance`,
  `(*Descriptor).normalizeRangeMembers`); grep tests for `frame.Function` and

  `util.AllocationsPerCall`; build inputs and plans outside measurement.
