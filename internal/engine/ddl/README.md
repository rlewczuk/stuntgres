# internal/engine/ddl

The contract every package that stages catalog changes shares with the
engine. `routine`, `typedef` and `extension` used to declare their own
statement authority and stage with nearly the same methods; this package
holds them once, and the feature hosts embed them. It sits at layer L8 of
[ENGINE-SPLIT.md §3](../../../docs/ENGINE-SPLIT.md#3-target-architecture):
above `session` (it names `session.NoticeLevel`), below the feature packages.
It imports only `access`, `authorization`, `catalog`, `ids`, `parser`,
`session`, `sqlstate` and the standard library, and never `analyze`, a
feature package or the engine. See
[ENGINE-SPLIT-ddl.md](../../../docs/ENGINE-SPLIT-ddl.md).

## What it owns

- **`Authority`**: the statement authority as an opaque value
  (`access.Environment` plus the `DDLAuthority` marker). Handlers keep it by
  value. A host method that changes it (`CreationNamespace`, `Recapture`)
  returns a new one and leaves its argument alone, so an implicit namespace
  or a peer recapture stays local to the helper that made it.
- **`Stage`**: the private catalog change (`Create`, `Replace`,
  `UpdateDescriptor`, `Get`, `LookupName`). The engine stage behind it keeps
  its lifecycle checks: `Create` and `Replace` fail on a discarded or
  published stage.
- **`Allocator`**: `AllocateOID` and `Revision`, handed out in the order the
  handlers ask, so Dump output stays byte-identical.
- **`TypeStaging`**: the autogenerated array of a new type and its creation
  ACL.
- **`Host`**: `Allocator` plus authority views, creation namespaces, the
  CREATE check, namespace search (type, conversion and operator names),
  function lookup, dependency descriptions, the stage and its reads, the
  creation ACL, drop targets, notices and the statement context.
- **Helpers**: `Check(h, auth, req)` pairs a view with its own authority as
  the environment, `ObjectRef(h, auth, a)` stamps a reference with the
  view's catalog epoch, and `Notice(h, code, message)` emits a NOTICE.

## Lock rule

Every `Host` method runs with `Engine.mu` held. None takes or releases it,
and none waits on the lock manager. The package adds no mutex.

## Who embeds it

- `routine.DDLHost` embeds `Host`; `typedef.StageHost` embeds `Host` and
  `TypeStaging`; `extension.Host` embeds `Allocator`, and `extension.Stage`
  embeds `Allocator` and `TypeStaging`. The extension handlers take an
  `Authority` and check it through the `access.View` passed beside it.
- In the engine, `AuthorizationView` is the only `Authority`
  (`ddlAuthorityOf` recovers it and panics on another kind). The adapters
  are `schemaHost` (`schema_host.go`), `typedefHost` (`typedef_host.go`, a
  defined type over `schemaHost` whose shared methods delegate to it) and
  `extensionHost` (`extension_host.go`), which wraps the stage and is never a
  defined type over `CatalogStage`.

## What stays in the engine

`Engine.mu`, authority capture, stage begin and publication, namespace
lookup and search paths (they need `analyze`), and the schema statement
dispatch (`schema.go`).

## Testing

Run from the repository root under the shared
[testing policy](../../../docs/TESTING.md). The package tests build a catalog
owner, a seeded role root and a TEMP namespace without an engine, and pin
that `Check` uses the authority as the environment, that `ObjectRef` stamps
the catalog epoch and that `Notice` emits NOTICE level:

```sh
timeout 900s make check RUN='^Test(CheckUsesAuthorityAsEnvironment|ObjectRefStampsCatalogEpoch|NoticeEmitsNoticeLevel)$'
```

The engine adapters are pinned by `TestSchemaHostRecaptureLeavesArgument`
and the `TestTypedefHost` tests in the engine package.
