# internal/engine/ddl

The contract every package that stages catalog changes shares with the
engine: the statement authority, the stage, the allocator and the host
methods `routine`, `typedef`, `extension`, `fdw` and `role` need. Feature
hosts embed these instead of declaring their own. The package also holds the
schema-level DDL decisions, the CREATE DATABASE decisions and the tablespace
and LOAD/CHECKPOINT validators. CHECKPOINT uses the current principal's existing
INHERIT closure for `pg_checkpoint`, then rejects unavailable WAL/fsync work;
it never stages catalog, data or physical statistics changes.

It sits at layer L8 of
[ENGINE-SPLIT.md §3](../../../docs/ENGINE-SPLIT.md#3-target-architecture):
above `session` (it names `session.NoticeLevel`), below the feature packages.
It imports only `access`, `authorization`, `catalog`, `ids`, `parser`, `settings`,
`session`, `sqlstate`, `sqltype` and the standard library, and never
`analyze`, a feature package or the engine.

## What it owns

- **`Authority`**: the statement authority as an opaque value
  (`access.Environment` plus the `DDLAuthority` marker). Handlers keep it by
  value. A host method that changes it (`CreationNamespace`, `Recapture`)
  returns a new one and leaves its argument alone, so an implicit namespace
  or a peer recapture stays local to the helper that made it.
- **`Stage`**: the private catalog change (`Create`, `Replace`,
  `UpdateDescriptor`, `Get`, `LookupName`). The engine stage behind it keeps
  its lifecycle checks: `Create` and `Replace` fail on a discarded or
  published stage.
- **`Allocator`**: `AllocateOID` and `Revision`, handed out in the order the
  handlers ask, so Dump output stays byte-identical.
- **`TypeStaging`**: the autogenerated array of a new type and its creation
  ACL.
- **`Host`**: `Allocator` plus authority views, creation namespaces, the
  CREATE check, namespace search (type, conversion, operator and function
  names), function lookup, dependency descriptions, the stage and its reads,
  the creation ACL, drop targets, notices and the statement context.
  `Host.RecordDependencyPath` records the path and returns its error; DROP
  SCHEMA stops on it, the other handlers ignore it.
  Creation tablespace policy consumes admitted operation settings and supplied
  coherent authority; the host owns TEMP transaction/list selection. Synthesis
  carries the same authority through partition-index staging, preserving the
  permanent clone's separate no-CREATE-check path. `PrepareTempTablespaces`
  shares provider resolution between interactive validation and retained filtering;
  destination checking consumes only the selected member, never the whole list.
- **Helpers**: `Check(h, auth, req)` pairs a view with its own authority as
  the environment, `ObjectRef(h, auth, a)` stamps a reference with the view's
  catalog epoch, and `Notice(h, code, message)` emits a NOTICE.
  `GeneratedRelationName` (`naming.go`) chooses PostgreSQL's name for an
  implicit relation (index, owned sequence, LIKE index): table and column
  clipped to 63 bytes on rune boundaries, then the label with the first free
  numeric suffix.
- **Command annotations** (`command.go`): `CreateCommand` and `ReplaceCommand`
  record the explicitly selected base command only after the checked stage
  mutation succeeds. `RecordCommand` attaches an actual returned object address
  independently of descriptor changes; companion arrays, row types, recursive
  descendants and payload rewrites keep ordinary stage mutations unless they
  execute a separate base command. An optional stage collector keeps pure
  catalog hosts independent of lexical event state. Core admits staged receipts
  with the ordinary successful publication/overlay transfer, preserving repeated
  addresses rather than deriving or deduplicating commands from catalog diffs.
  `AdmitNoopCommand` is only for a successful, resolved command whose owner
  returns without a publishable stage, including unchanged ownership/schema and
  unchanged collation version refresh. It records directly in that owner's
  collector without replacing a descriptor or allocating a revision. The command
  owner preserves its authorization, error and notice ordering before admission.
  Skipped creation, invalid returned addresses and failures must not use it.
  Conversely a no-mutation result is not itself a reason to omit a valid receipt.
  Callers own command-specific grouping, tags and subobject addresses; these
  helpers neither resolve targets nor grant publication or callback authority.
- **`SchemaHost`**: `Host` plus what CREATE and DROP SCHEMA need:
  `StageSchemaTable` (one `CREATE TABLE` element, analyzed as the schema owner
  with the new namespace first in the path, on the host's own copy of the
  authority), `StageSchemaDependents` (the dependency closure of dropped
  schemas), `RemoveObject`, `AddCascadeNotice` and `RelationDiagnostic`.
- **Schema-level DDL**: `StageCreateSchema`, `StageAlterSchema` (needs only
  `Host`) and `StageDropSchema` hold every decision of those statements, in
  PostgreSQL's order: owners, the database CREATE gate, the SET ROLE rule,
  reserved `pg_` names, duplicates and IF [NOT] EXISTS notices, the namespace
  descriptor and ACL, element checks, dependent classification, the 2BP01
  diagnostic, cascade notices and removals. Each returns `(staged, err)`;
  `false, nil` means there is nothing to publish.
  `ResolveSchemaCreation` shares effect-free owner/database authority checks with
  conditional creation readmission. Schema and embedded-table candidates use the
  same owner-private stage; later elements see earlier elements without changing
  the caller's role or path.
  `CaptureSchemaDrop` records every ordered name/ref or conditional absence with
  its domain/epoch. `StageDropSchema` consumes that manifest under one coherent
  current-authority/catalog lock window, validating all bindings before notices
  or removals; it never re-resolves a replacement from the original names.
- **Statistics** (`statistics.go`, `statistics_target.go`): stage schema-bound
  definitions with immutable simple keys and ordered expression recipes, ordered
  admission and atomic DROP targets. A narrow host binds recipes using the core
  single-relation binder; ddl never imports an evaluator. One expression forbids
  explicit kinds before kind-name validation. Bounded object-target mutation normalizes bounds/warnings
  before lookup/ownership and replaces only metadata, preserving collected facts.
  Rename and namespace movement shallow-copy the descriptor, retaining original
  address, relation, selection and expression backing. Rename checks schema CREATE
  before collisions (including self). Schema movement resolves the source, then
  resolves and checks destination CREATE before its same-schema no-op or the
  actual transition/source-owner/conflict checks.
  Its bounded namespace host permits system destinations without bypassing CREATE
  or temporary/TOAST restrictions. Constructors preserve ordinary CREATE policy;
  genuine isolated imports alone may reconstruct a moved system-schema definition.
- **Text-search parsers** (`ts_parser.go`): CREATE validates located options in
  written order against exact routine input/result signatures. Valid repetitions
  overwrite earlier values; absent optional HEADLINE remains zero. CREATE and
  rename/schema ALTER require superuser authority. SET SCHEMA checks destination
  existence and CREATE permission before the parser-specific superuser check.
  Its scoped destination resolver permits system namespaces without relaxing
  ordinary user-CREATE namespace protection. ALTER superuser denial describes the
  current object using ordinary search-path visibility and dependency spelling.
  DROP permits containing-schema owners without inventing parser ownership;
  unrelated users receive the ordinary superuser-required diagnostic. A seeded
  parser's DROP rejection uses the current dependency description's search-path
  visibility and identifier quoting before membership restrictions. All names,
  callback dependencies and collisions validate privately before the ordinary
  single-stage publication.
- **Text-search configurations** (`ts_configuration.go`): ordinary private stages
  resolve namespace CREATE and owner authority, COPY/PARSER, every ordered mapping
  action, rename/schema/owner transfers and DROP targets. Token aliases resolve
  against the referenced parser's checked LEXTYPES authority. Mapping candidates own both slice
  levels; all operands validate before one replacement, without resource I/O.
  `ConfigurationHost.SearchConfigurationNamespaces` resolves every existing source
  operand: ALTER/DROP targets, COPY/PARSER, mapping dictionary lists and old/new
  replacement dictionaries. Current caller namespace USAGE precedes ownership
  and source lookup, including staged native replay; trusted destination
  construction grants no source authority. Utility diagnostics have no expression
  position, without mutating caller authority or AST positions or changing generic
  dictionary/parser/operator lookup. Destination creation keeps its own policy.
  Schema dependency classification includes configuration descriptors, so
  RESTRICT reports their actual dependency and CASCADE retires their closure.
- **Generic namespace movement** (`namespace.go`): `StageObjectNamespace` stages
  statistics, operator/class/family, collation/conversion and text-search
  parser/template/dictionary/configuration identities with
  real owner or ownerless-superuser admission, destination CREATE and exact name
  claims. Routine, type and relation mechanics remain with their actual owners.
  `catalog.CheckSetNamespace` is shared mechanical admission, not authorization.
  Parser movement checks namespace legality and same-namespace admission before
  ownerless superuser authority, then destination permission/collision; its
  immutable callback tuple and current e-link are retained. Extension membership
  ADD/DROP requires bare `must be superuser` after extension ownership, not a
  fabricated parser owner. Ordinary parser ALTER keeps its distinct existing
  permission ordering.
- **Tablespaces**: `CreateTablespace(ctx, view, s)` validates CREATE
  TABLESPACE over the `access.View` and, once valid, fails with 0A000
  (`TablespacePhysicalUnsupported`); it never stages. `TablespaceRef(view,
  name)` resolves a tablespace for GRANT, ALTER TABLESPACE and ALTER TABLE SET
  TABLESPACE. `CheckAlterTablespaceCreate(view, env, ref)` checks CREATE on a
  SET TABLESPACE or ALL IN TABLESPACE destination (none for `pg_default`),
  and `AlterTablespaceKind(relation)` rejects SET TABLESPACE on relation
  kinds without their own storage (42809). `AlterAllTablespace(view, env, s)`
  decides ALTER ... ALL IN TABLESPACE (owner membership, both references,
  `pg_global` rejection 22023, destination CREATE, success for the same
  tablespace, 0A000 otherwise); it never selects or locks a relation.
- **Tablespace inquiries** (`tablespace_info.go`): `TablespaceLocation` and
  `TablespaceDatabase` compute `pg_tablespace_location` and one
  `pg_tablespace_databases` row over the statement's retained `catalog.Read`.
  `TablespaceDatabase` returns its 01000 WARNING beside a NULL value; the caller
  emits it.
- **SECURITY LABEL**: `SecurityLabel(ctx, view, s)` checks cancellation/current
  authority and returns exact absent-provider 22023 diagnostics before target
  lookup or ownership. Omitted and empty-string providers differ; decoded names
  are not Go-escaped in diagnostics. PostgreSQL's native C provider ABI/loading
  and SELinux/MAC integration are unavailable. No provider/store is fabricated.
- **LOAD**: `Load(ctx, view, s)` checks the current actor's SUPERUSER
  attribute, then PostgreSQL's plugin prefix/suffix restriction and
  slash-containing filename macro validation; once valid it returns 0A000
  (`LoadUnsupported`). It never expands paths, inspects files, stages objects
  or allocates catalog identities. `schemacmds.ExecuteLoad` owns the
  argument count, the mutex and fresh authority capture; Prepare performs none
  of these execution checks.
- **CHECKPOINT**: `Checkpoint(ctx, view, s)` checks current inherited
  `pg_checkpoint` authority, then returns `CheckpointUnsupported` without
  performing physical work. `schemacmds.ExecuteCheckpoint` captures fresh
  authority under the engine mutex; preparation checks neither permission nor
  physical availability.
- **CREATE DATABASE** (`database.go`): `ParseCreateDatabaseOptions` checks
  the option list (duplicates, unknown names, malformed values) with nothing
  held and before any authority check, and returns `CreateDatabaseOptions`.
  `CreateDatabaseOwner(roles, current, name)` resolves the owner over the
  captured `authorization.Read` and checks CREATEDB or SUPERUSER and the SET
  ROLE rule. `CheckCreateDatabase(name, options, exists)` runs the admission
  checks in PostgreSQL's order: template, encoding, LC_COLLATE/LC_CTYPE, the
  unsupported capability, then the duplicate name. `exists` answers whether a
  database name is registered. Both run under `Engine.Mu` and take no lock.

## Lock rule

Every `Host` method runs with `Engine.Mu` held. None takes or releases it,
and none waits on the lock manager. The package adds no mutex.

## Who embeds it

- `routine.DDLHost` embeds `Host`; `typedef.StageHost` embeds `Host` and
  `TypeStaging`; `extension.Host` embeds `Allocator`, and `extension.Stage`
  embeds `Allocator` and `TypeStaging`. The extension handlers take an
  `Authority` and check it through the `access.View` passed beside it.
- In the engine, `AuthorizationView` is the only `Authority`
  (`DDLAuthorityOf` recovers it and panics on another kind). The core staging
  adapter is `DDLHost` (engine, operation, catalog stage; `ddl_host.go`): the
  `Host` methods, the methods core paths call and those unrelated family
  hosts share. The family hosts embed it and keep its layout:
  `tablecmds.TableHost` (`table.Host`, `index.Host`, `partition.Host`,
  `fdw.Host`), `TypeHost` and `ViewHost` over `TableHost`,
  `schemacmds.RoutineHost`, `rolecmds.RoleHost` and `schemacmds.SchemaHost`.
  The `schemacmds` extension host (`extension_host.go`) stays separate: it
  captures one view and implements `extension.Host` and `extension.Stage`. No adapter is a defined type over `CatalogStage`, so its
  unchecked `Create`/`Replace` are never promoted.
- **Adding a feature host:** embed `Host` and declare no `Authority` or
  `Stage` of your own. In the family package, put the methods on the family
  host its callers build, embedding `DDLHost` or another family host so that Go
  promotes the shared methods. A method belongs on `DDLHost` only when core
  calls it or unrelated family hosts share it. Never copy a shared method
  body.

## What stays in the engine

`Engine.Mu`, authority capture, stage begin and publication are core's. The
schema statement executors are [`schemacmds`](../schemacmds/README.md)'s
(`schema.go`): `ExecuteSchema` (partition 0A000 pre-checks, locks,
publication and the cascade notice), `stageSchemaLocked` (capture, the early
actor read that gates every staged statement, one call per statement),
`stageSchemaDomainsLocked` and, in `tablecmds`, `SchemaTableLocked` (a
forwarder to `table.StageCreateTable`).
The engine owns transaction admission, namespace existence/removal locks and
exact staged destination-name claims. It publishes schema/table/dependency
candidates through the ordinary journal, with no separate schema undo path.
`schemacmds.ExecuteCreateTablespace` keeps the argument count
check, the lock and the authority capture; `AlterAllTablespaceLocked` keeps
the argument count check and the deferred `Engine.Mu` unlock, and
`statementHost.TablespaceLocation`/`TablespaceDatabase` keep the retained
snapshot and owner check and emit the returned warning.
`rolecmds.ExecuteCreateDatabase` keeps the argument count check, `Engine.Mu`,
the authority capture (`databaseCreateOwnerLocked`), the `exists` answer from
the cluster's targets and the context check; `createDatabaseTarget` (private
construction and the owner re-check) and `publishDatabaseTargetLocked` stay
with it.

## Testing

The package tests build a catalog owner, a seeded role root and a TEMP
namespace without an engine, and pin that `Check` uses the authority as the
environment, that `ObjectRef` stamps the catalog epoch, that `Notice` emits
NOTICE level, creation error positions, which relation kinds SET
TABLESPACE accepts, that `TablespaceDatabase` returns its warning and the
CREATE DATABASE admission order (`TestCheckCreateDatabaseOrder`). Engine tests pin the adapter (`TestDDLHost*` in
`ddl_host_test.go`; `TestDDLHostStageSchemaTableKeepsAuthority` checks that
`StageSchemaTable` leaves the caller's authority unchanged and stages the
table with the given owner and namespace), LOAD/CHECKPOINT validation and executor
non-publication and CREATE TABLESPACE non-publication (in
`internal/engine/schemacmds`), the tablespace inquiry adapter
(`TestTablespaceInfo*`, in `internal/engine/core`) and CREATE DATABASE
publication (`TestDatabaseCreate*`, in `internal/engine/rolecmds`).

```sh
make check RUN='^Test(CheckUsesAuthorityAsEnvironment|ObjectRefStampsCatalogEpoch|NoticeEmitsNoticeLevel|CreationErrorPositionsAtFirstNamePart|AlterTablespaceKind|TablespaceDatabaseReturnsWarning|CheckCreateDatabaseOrder)$$'
make check RUN='^Test(DDLHost|Load(Validation|ExecutorNoPublication)$$|CheckpointExecutorNoPublication$$|TablespaceExecutorNoPublication$$)'
make check RUN='^TestReference((Alter)?Schema|.*Tablespace|Load|Checkpoint|DatabaseCreate)'
```

Public LOAD scenarios are in
[reference/extensions](../../../reference/extensions/README.md#testing).
