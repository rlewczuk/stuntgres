# PG18-CAT-PG-CAST — Read pg_cast metadata

## Contract and ownership

`pg_catalog.pg_cast` is readonly relation **2605**, namespace **11**, with PUBLIC
SELECT and these six ordered, known-NOT-NULL native columns:

| Attribute | Name | Type | Fixed type OID |
|---|---|---|---:|
| 1 | oid | OID | 26 |
| 2 | castsource | OID | 26 |
| 3 | casttarget | OID | 26 |
| 4 | castfunc | OID | 26 |
| 5 | castcontext | internal `"char"` / CHAR | 18 |
| 6 | castmethod | internal `"char"` / CHAR | 18 |

All usages have typmod -1 and collation0. Attribute origins are relation2605,
attributes1–6. Ordinary catalog lookup, aliases, joins, filters, sorting,
prepared statements and stored views use the existing query-source pipeline.
No pg_type, pg_proc or pg_attribute SQL inventory is introduced.

The **type/coercion owner** declares catalog facts: baseline-backed facts reside
in `castSpec` beside the existing execution provider; special character, BOOL,
JSON and typmod facts reside in `internal/sqltype/cast_catalog.go`. The owner
builds one private fixed array during package initialization and returns indexed
value copies through `CastMetadataCount` / `CastMetadataAt`. Readers cannot
mutate definitions; indexed reads allocate nothing. Generated local row IDs
**20000–20064** are assigned explicitly per definition, not generated by each
query or inferred from successful planning. Future owner additions must preserve
existing IDs. These are not PostgreSQL's generated row IDs. Type/function OIDs
and relation identity are exact fixed PostgreSQL identities.

The engine's dedicated `capturePGCast` validates current descriptor ownership
and both endpoints, then projects the owner values using owned OID/CHAR columns.
It allocates one row bag and one contiguous value buffer; it neither enumerates
unrelated relations nor plans coercions per read. It checks cancellation before
materialization and between rows, returning the original error and no partial
source. Missing owner/type facts fail as invariants, never successful omissions.

Catalog **method** is not the native opcode. For example INT4→OID and OID→INT4
are PostgreSQL binary rows even though native execution must perform signed OID
conversion; JSON conversions use catalog I/O, while self typmod rows describe
function-based sizing despite native identity-plan execution.

8 genuine typmod self rows and 2 JSON rows. Context `i` admits Implicit,
Assignment and Explicit; `a` admits Assignment and Explicit; `e` admits only
Explicit. Invalid input or overflow remains a value error, not absent support.
Method `f` requires a nonzero function OID; methods `b` and `i` use zero.

## Omissions are not a conversion inventory

PostgreSQL pg_cast itself omits automatic scalar/string I/O, domain/base
conversions and ordinary identity conversions. Thus supported INT4↔TEXT,
FLOAT8→TEXT, OID→TEXT or domain/base conversions do not imply catalog rows;
INT4→INT4, TEXT→TEXT and BOOL→BOOL have no genuine typmod row.

Additional native omissions deliberately preserve incomplete existing providers:
NAME cross casts, REGCLASS cross casts, BIT/VARBIT cross/self casts,
PG_NODE_TREE→TEXT and family-local internal-CHAR→TEXT do not have the full
public context closure necessary to advertise PostgreSQL's rows. JSONB→numeric,
BOOL, integer or float and TIME↔INTERVAL have no admitted provider. No geometric,
network, money, XML, range or unrepresented type casts are invented. Special
unknown REGCLASS input is not evidence for a known TEXT→REGCLASS cast.

CREATE/DROP CAST, new cast execution, dynamic owner registration, a second type
registry and a general catalog rollout are excluded. Future cast implementation
owners must attach exact facts only when their entire declared closure works.

## Lifetime, diagnostics and public adapters

Fixed cast rows are reconstructed by existing initialization through native
Reset/Restore. Dump serializes user definitions/data, never virtual cast rows.
Existing eager captured results retain old descriptors/values; new captures use
new owned type generations with the same fixed metadata/local row identities.
Failed or canceled Restore leaves committed user data and the cast bag unchanged.
Actual native user Dump SQL is replayed against PostgreSQL, which has no invented
Reset/Restore control API.

Missing columns use PostgreSQL42703 English diagnostics and one-based character
positions (including UTF8); malformed and overflowing OID inputs remain22P02
and22003; OID→SMALLINT remains42846. Held parameter failures preserve handles
and valid later execution. Native virtual-source writes return0A000
`catalog source mutation is unsupported`; row locking returns0A000
`row locking is not supported for virtual catalog relations`, even empty.
These restrictions are not PostgreSQL physical-superuser catalog claims.
Deterministic precanceled native APIs return ordinary context.Canceled, not an
invented SQLSTATE or portal diagnostic.

Native OID raw values/ScanType are int64; CHAR values/ScanType are string.
Pinned pq v1.12.3 reports **interface{} ScanType for all six columns**, with raw
OID decimal bytes and CHAR string values. Both expose unavailable Length and
DecimalSize here; pq Nullable is unknown while native is known false. Both
current adapters attach the actual unnamed-portal parameter Context to input
errors: `unnamed portal parameter $1 = '...'` for nonempty decoded input and
`unnamed portal parameter $1 = ''` for empty input, without a query Position.
The complete shared diagnostic expectation is asserted without backend-specific
Context normalization; raw codec assertions remain unchanged.

## Verification and runnable feature smoke

The root's initial pinned PostgreSQL18.0 oracle validated the complete shared
reference family after source-grounded pq ScanType correction; the subsequent
native red established missing pg_catalog.pg_cast. Production/units must still
pass fresh root verification; those observations are not an implementation pass.

From the assigned repository worktree, each selected check has a900-second deadline:

```sh
make check RUN='^TestReferencePGCast'

make check RUN='^TestPGCast'
make check RUN='^TestReferencePGCastFeatureSmoke$'
make check REFERENCE=1 RUN='^TestReferencePGCastFeatureSmoke$'
```

The smoke asserts empty shape, the eight-row representative metadata subset,
full65 identity invariants, held valid/missing/NULL/error/recovery frames, implicit
widening, signed OID boundary, BOOL text, JSON I/O, VARCHAR truncation versus
atomic assignment failure, UTF8 missing-column position14, retained native
catalog controls and actual dumped user SQL replay. It is an actual SQL/API
scenario, not test discovery or an echoed golden. Both modes and the affected
coercion/catalog families in [TESTING](../TESTING.md) precede review. Ordinary
quickcheck and post-merge finalcheck (one1800-second gate) remain required.
