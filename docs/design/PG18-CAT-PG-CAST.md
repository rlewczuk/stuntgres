# PG18-CAT-PG-CAST — Read pg_cast metadata

## Contract and ownership

`pg_catalog.pg_cast` is readonly relation **2605**, namespace **11**, with PUBLIC
SELECT and these six ordered, known-NOT-NULL native columns:

| Attribute | Name | Type | Fixed type OID |
|---|---|---|---:|
| 1 | oid | OID | 26 |
| 2 | castsource | OID | 26 |
| 3 | casttarget | OID | 26 |
| 4 | castfunc | OID | 26 |
| 5 | castcontext | internal `"char"` / CHAR | 18 |
| 6 | castmethod | internal `"char"` / CHAR | 18 |

All usages have typmod -1 and collation0. Attribute origins are relation2605,
attributes1–6. Ordinary catalog lookup, aliases, joins, filters, sorting,
prepared statements and stored views use the existing query-source pipeline.
No pg_type, pg_proc or pg_attribute SQL inventory is introduced.

The **type/coercion owner** declares catalog facts: baseline-backed facts reside
in `castSpec` beside the existing execution provider; special character, BOOL,
JSON and typmod facts reside in `internal/sqltype/cast_catalog.go`. The owner
builds one private fixed array during package initialization and returns indexed
value copies through `CastMetadataCount` / `CastMetadataAt`. Readers cannot
mutate definitions; indexed reads allocate nothing. Generated local row IDs
**20000–20072** are assigned explicitly per definition, not generated by each
query or inferred from successful planning. Future owner additions must preserve
existing IDs. These are not PostgreSQL's generated row IDs. Type/function OIDs
and relation identity are exact fixed PostgreSQL identities.

The dedicated `capturePGCast` producer (now in `internal/engine/pgcatalog`) validates current descriptor ownership
and both endpoints, then projects the owner values using owned OID/CHAR columns.
It allocates one row bag and one contiguous value buffer; it neither enumerates
unrelated relations nor plans coercions per read. It checks cancellation before
materialization and between rows, returning the original error and no partial
source. Missing owner/type facts fail as invariants, never successful omissions.

Catalog **method** is not the native opcode. For example INT4→OID and OID→INT4
are PostgreSQL binary rows even though native execution must perform signed OID
conversion; JSON conversions use catalog I/O, while self typmod rows describe
function-based sizing despite native identity-plan execution.

User declarations are immutable `catalog.Cast` descriptors, class2605, indexed
by ordered source/target pair. They have no owner, ACL or namespace. The COW
pair index is shared by unmodified snapshots and rebuilt/remapped with ordinary
candidate/replacement publication. `pg_cast`, DROP closure and dump ordering
share the cast's endpoint/function/signature-adapter dependencies.

`catalog.SelectCoercion` and `catalog.CanCoerce` are the single effect-free
declared-pair selection and feasibility authority for analyzer and routine
callers. Context-ineligible declarations refuse before generic fallback;
domain/base and array recursion preserve existing rules, including outer
array typmod/collation projection. Catalog refusals carry shared SQLSTATE
diagnostics without positions. Semantic expression construction remains in
`analyze`/`plan`; catalog selection never binds or evaluates a routine.

## Omissions are not a conversion inventory

PostgreSQL pg_cast itself omits automatic scalar/string I/O, domain/base
conversions and ordinary identity conversions. Thus supported INT4↔TEXT,
FLOAT8→TEXT, OID→TEXT or domain/base conversions do not imply catalog rows;
INT4→INT4, TEXT→TEXT and BOOL→BOOL have no genuine typmod row.

Incomplete builtin NAME, REGCLASS and BIT/VARBIT families remain omitted from
the fixed metadata inventory; an independently declared user edge does not
silently advertise or replace an omitted builtin family.

CREATE CAST supports WITH FUNCTION, WITH INOUT and WITHOUT FUNCTION, plus
AS ASSIGNMENT/AS IMPLICIT. A declared context refusal blocks automatic IO
fallback; unknown literals still use the target input codec directly.
The analyzer owns catalog-aware selection and selected SQLRoutineExpr execution,
while sqltype owns fixed providers and native binary representations. Function
probes are pure and preserve existing exact/category/preferred/variadic ranking.
Binary representation selection is not PostgreSQL layout validation: the DDL
owner first enforces superuser, physical facts and excluded categories. Genuine
unsupported native ABI mappings fail0A000 `binary cast representation is not
supported`; a malformed payload in an admitted family fails0A000 `binary cast
value is not representable in embedded mode`. FLOAT4 signaling NaNs are not
an unsupported boundary.

## Lifetime, diagnostics and public adapters

Fixed rows are rebuilt by native Reset/Restore and omitted from Dump. User casts
are ordinary qualified declarations in the dependency graph. Only FLOAT4 NaN
words other than canonical positive quiet NaN (`0x7fc00000`) need raw replay:
finite values, subnormals, signed zero, infinities and canonical NaN retain the
existing canonical SQL literals. `Value.Float4NeedsRawReplay` is the scalar
authority, recursively shared by literal rendering and bootstrap detection over
visible row values and stored constants. Raw replay uses the final xid→real
binary edge when available, otherwise a real temporary
binary declaration before stored recipes/data and real DROP before the final
conflicting declaration (or at completion when absent). Typed XID[] word literals
retain direct REAL[] dimensions/lower bounds; composite array rows use existing
INSERT target slices to preserve nondefault bounds without text NaN round trips.
Restore admits ordinary CREATE/DROP CAST through isolated staging and remaps the
final endpoint/routine/adapter identities before one cancellation-checked replace.
Frozen IO/binary and typed-array function consumers contribute direct retained-IR
requirements to dump events. If their pair is absent or has a different final
method/routine/context, a real temporary declaration surrounds the consumer's
declaration (or deferred recipe phase), then is dropped. Actual conflicting
final declarations follow those windows exactly once. Signature binary adapters
precede temporary function rows and are removed in reverse dependency order.
Original context/typmod and array element templates remain authoritative; no
AS IMPLICIT broadening or transitive view/generation graft scan substitutes
another meaning. Conflicting recipes for the same pair in one indivisible
consumer are reported with the exact event/pair rather than silently retargeted.
Minimizing evaluated literals never removes a genuine selected frozen cast
recipe, even when its input or eventual result is finite.
Foreign tables contribute only their directly rendered defaults, generations
and checks, without pretending to be physical dump relations. Inline defaults
share their actual CREATE FOREIGN TABLE window. Conflicting default epochs
split only affected attributes into real ALTER FOREIGN TABLE SET DEFAULT
statements; this does not enable global default deferral.
Deferred foreign statements retain the existing post-events/data/materialized/
policies/RLS/rules section. Each statement has its own selected cast window, and
the same window planner postpones conflicting authentic final cast declarations
(including dependent cast adapters) until that section finishes, exactly once.
Restore's existing deferred-default admission accepts ordinary and foreign
defaults carrying retained selected cast IR; normal provider validation, ALTER
authority, usage and dependency capture still apply, with no default evaluation.
`TestReferenceCastDefinitionForeignDefaults` uses portable metadata-only
`NO HANDLER NO VALIDATOR` wrapper/server definitions, independent old/fresh
routine dependencies, ordinary default values, final cast metadata and native
Dump/Reset/Restore. The actual native-emitted SQL bytes also execute unchanged
on PostgreSQL and repeat the same catalog/value assertions; no remote provider
identity or remote query is required.
Existing eager captured results retain old descriptors/values; new captures use
new owned type generations with the same fixed metadata/local row identities.
Failed or canceled Restore leaves committed user data and the cast bag unchanged.
Actual native user Dump SQL is replayed against PostgreSQL, which has no invented
Reset/Restore control API.

Missing columns use PostgreSQL42703 English diagnostics and one-based character
positions (including UTF8); malformed and overflowing OID inputs remain22P02
and22003; OID→SMALLINT remains42846. Held parameter failures preserve handles
and valid later execution. Native virtual-source writes return0A000
`catalog source mutation is unsupported`; row locking returns0A000
`row locking is not supported for virtual catalog relations`, even empty.
These restrictions are not PostgreSQL physical-superuser catalog claims.
Deterministic precanceled native APIs return ordinary context.Canceled, not an
invented SQLSTATE or portal diagnostic.

Native OID raw values/ScanType are int64; CHAR values/ScanType are string.
Pinned pq v1.12.3 reports **interface{} ScanType for all six columns**, with raw
OID decimal bytes and CHAR string values. Both expose unavailable Length and
DecimalSize here; pq Nullable is unknown while native is known false. Both
current adapters attach the actual unnamed-portal parameter Context to input
errors: `unnamed portal parameter $1 = '...'` for nonempty decoded input and
`unnamed portal parameter $1 = ''` for empty input, without a query Position.
The complete shared diagnostic expectation is asserted without backend-specific
Context normalization; raw codec assertions remain unchanged.

## Verification and runnable feature smoke

The root's initial pinned PostgreSQL18.0 oracle validated the complete shared
reference family after source-grounded pq ScanType correction; the subsequent
native red established missing pg_catalog.pg_cast. Production/units must still
pass fresh root verification; those observations are not an implementation pass.

From the assigned repository worktree, each selected check has a900-second deadline:

```sh
make check RUN='^TestReferencePGCast'
make check REFERENCE=1 RUN='^TestReferencePGCast'
make check RUN='^TestCastCatalog'
make check RUN='^TestPGCast'
make check RUN='^TestReferencePGCastFeatureSmoke$'
make check REFERENCE=1 RUN='^TestReferencePGCastFeatureSmoke$'
```

The smoke asserts empty shape, the eight-row representative metadata subset,
full fixed73 identity invariants, held valid/missing/NULL/error/recovery frames, implicit
widening, signed OID boundary, BOOL text, JSON I/O, VARCHAR truncation versus
atomic assignment failure, UTF8 missing-column position14, retained native
catalog controls and actual dumped user SQL replay. It is an actual SQL/API
scenario, not test discovery or an echoed golden. Both modes and the affected
coercion/catalog families in [TESTING](../TESTING.md) precede review. Ordinary
quickcheck and post-merge finalcheck (one1800-second gate) remain required.
