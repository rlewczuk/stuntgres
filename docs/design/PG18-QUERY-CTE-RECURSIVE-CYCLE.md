# Recursive CYCLE detection

## Scope and release authority

This extends the existing recursive SELECT CTE binder and producer with
`CYCLE keys SET mark [TO constant DEFAULT constant] USING path`. It does not
add SEARCH, recursive modifying definitions, general composite grouping, generic
record-array catalog providers, spill machinery or new equality providers.

Semantics follow [PostgreSQL 18 WITH cycle detection](https://www.postgresql.org/docs/18/queries-with.html#QUERIES-WITH-CYCLE)
and the pinned PostgreSQL 18.0 observations encoded in
`reference/query_core/query_cycle_*_test.go`. The parser grammar is source;
`grammar_gen.go` is regenerated by the root verification owner. Readiness and
this design are not claims of exercised verification.

## Binding and diagnostic precedence

The positioned AST retains ordered identifiers and optional constant syntax.
Marks use existing common-type, coercion and collation analysis before binding
the body. The retained SQL inequality authority is bound once, not reconstructed
for each comparison. Defaults are TRUE/FALSE. Grammar constants deliberately do
not admit parameters, postfix casts, signs or arbitrary scalar expressions.

The anchor finalizes original names, aliases and Usage before exposing the self
scan. Generated mark/path columns follow original columns. A pending invalid-key
error is retained while the self schema is exposed so body ambiguity and original
UNION width/type errors keep their established precedence. Invalid definitions
are rejected before they can become executable recipes. Generated-name checks
follow the body and key checks: mark membership across all original columns
first, then path membership, then mark/path equality. Original column order
cannot change that precedence; excess aliases cannot consume generated slots.

The existing identity-aware recursive legality walker still owns dependencies,
shadowing and prior body-WITH/SubLink restrictions. CYCLE adds SELECT-only UNION
operand and top-level self-source restrictions using those same identities.
Generated mark/path columns are hidden from qualified and unqualified stars in
queries contained in the owning WITH's CTE definitions, including sibling
definitions and nested queries. The existing lexical CTE bindings retain whether
their owning WITH's definition bodies are being analyzed. Completing that WITH's
definitions clears only their bindings' contained state; nested WITHs and
subqueries preserve the enclosing bindings' state. A nested WITH's external
query therefore exposes its own generated columns without exposing an enclosing
definition's hidden generated slots. Explicit lookup remains normal and detects
ambiguity. Outside those
definitions, stars expose original columns followed by mark/path.

Every CYCLE reference alias list is checked against the recipe's original width,
whether it is a worktable or an external scan. A prefix renames original columns
only; generated columns retain their declared names. Namespace rebasing, alias
copies and join composition preserve the star-visibility bit, including computed
merged columns. The contained state is analysis-only, not stored recipe state;
definition remapping retains the original-width recipe and bound projections.

## Occurrence-owned types and immutable ancestry

Each clause owns a concrete RecordShape (OID2249) and array (OID2287, `_record`)
over that exact record pointer. Members retain ordered keys and actual Usage,
including typmods and collations. These are expression authorities, not catalog
entries. Generic catalog `_record` remains lookup-only.

Every key occurrence is a non-NULL record even if all fields are NULL. The path
append owns one new array buffer and shares immutable earlier record values.
It never stringifies/reparses keys or mutates parent arrays. Existing canonical
array/composite codecs export the result; adapters add no serialization path.
Retained eager rows therefore remain valid after producer/catalog replacement.

`validExpressionUsageAt` descends through the occurrence array and record while
requiring exact current leaf generations. One memoized descriptor-pointer map
remaps the entire tree, preserving distinct same-OID occurrences and the exact
array-element/recipe-record relationship without mutating the source. Internal
`sameRecordUsage` checks shapes and leaves. Public statement signatures instead
retain PostgreSQL's stable record[] result identity: a key-only INT4→INT8 shape
change does not reject held raw/text paths. Ordinary scalar results still reject
changed types. This public rule does not authorize foreign internal descriptors.

## Equality, DISTINCT and exact parent provenance

Ordered key Grouping authorities are bound once. Their NOT DISTINCT semantics
make corresponding NULL fields equal and preserve installed numeric, BPCHAR,
NaN, domain and supported-array semantics. No global composite grouping provider
is installed. CYCLE owns structural record/path equality and matching hash
combination; hash collisions always require full tuple/path equality.

Recursive UNION DISTINCT retains all original fields, mark and full path.
Ordinary set grouping handles the original/mark prefix; the CYCLE authority
handles the generated path. Different ancestry to the same node is not a global
visited-node duplicate. Non-CYCLE recursive UNION remains unchanged.

The recursive candidate can arise from a reordered physical join. Hidden arm
projection slots retain the actual self worktable occurrence's mark/path using
its joined frame offset. They are not inferred from output index, frontier order
or mutable shared current-parent state. Only the public original outputs are
subject to the original UNION width/type contract. Stored rendering iterates
symbolic targets, not hidden projection slots.
Stored-layout validation keeps the anchor's original width distinct from the
augmented public/recursive-arm width. It checks original coercions on both arms,
parent mark/path Usage only on the recursive arm, and the ordinary DISTINCT
prefix separately from occurrence-owned path equality. Remapped definitions
retain these same widths; symbolic UNION rendering supplies only original
column labels and re-emits CYCLE to regenerate the public values.
Every CYCLE CTE reference's bridge aliases name only the original-column prefix:
PostgreSQL resolves reference aliases before rewriting generated columns, even
for the outer query. Generated mark/path slots keep their CYCLE-declared names
and remain in the renderer's complete slot map, including through explicit table
aliases and joins. Their names are reserved before original bridge labels are
deduplicated, so an original alias cannot force a generated column to be renamed.
Ordinary derived queries still alias their complete public output.


Anchors emit fallback mark plus one-record path. Recursive candidates compare
their current key record with that actual parent's path, append the current
record and emit even when it closes a cycle. Continuation is the retained SQL
`parent mark <> configured mark` predicate, keeping only TRUE. Equal custom
marks and NULL mark/default values can therefore suppress expansion immediately;
there is no independent Boolean visited flag overriding SQL semantics.

## Lifetime, publication and persistent recipes

Frontiers, hashes, cached mark values and accepted tuples belong to the existing
recursive producer invocation, never prepared/catalog definitions. Every Execute
and correlated invocation starts fresh. Context checks remain in path scans,
append, key hashing, comparison and duplicate-rejection loops. Existing CTE first
failure retention, once-only close and close-failure veto remain the only owners.
No second publication or catalog cache is introduced. Cancellation/late failure
therefore veto cursor or write publication through the existing statement owner.

Views and native Dump/Reset/Restore retain symbolic CYCLE syntax and physical
source dependencies, not runtime paths/frontiers or anonymous catalog types.
Each typed TO/DEFAULT constant also retains the typed-literal binder's analyzed
source Usage (exact descriptor, modifier and collation), separately from the
common output Usage. Symbolic rendering uses that source annotation through the
existing PostgreSQL type renderer; ordinary typed-literal binding reconstructs
the original explicit input conversion before common coercion. Recipe remapping
retags the retained source descriptors/collations with the same catalog mapper.
Thus `numeric(3,1) '1.25'` still rounds to `1.3` when paired with unconstrained
NUMERIC in either operand after native or PostgreSQL replay; raw `1.25` must
never be reintroduced using the unconstrained common output type.
Generated direct record[] persistent columns reject with 42P16 at execution,
not Prepare. Ordinary columns, marks and path::text remain valid stored outputs.
Existing-view replacement validates its name/type prefix before persistent
record[] rejection; appended paths still reject before publication.
The Restore admission whitelist is unchanged; its single complete-script parse
retains full-script positions for both syntax and later binding failures.
Transient public coverage asserts no pg_class entry and unchanged native Dump,
and retains generated values across replacement. PostgreSQL additionally checks
pg_type for no transient type entry. Native explicitly rejects that pg_type
inspection with positioned 42P01: this part does not install a pg_type provider.
Private ownership coverage checks that catalog RECORD/RECORD[] identities remain
lookup-only and distinct from the occurrence authorities. Ordinary TEXT results,
including text paths, retain the existing Length `(MaxInt64,true)` contract on
both adapters; CYCLE does not change metadata providers. Stored native view
columns retain known-nullable `(true,true)` while pq exposes `(false,false)`;
raw scan types, lengths and numeric precision/scale are checked before iteration.
